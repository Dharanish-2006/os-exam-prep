Answers

Part A

1–6

1. Process: a program in execution, with its own memory, registers and resources, managed by the OS.

2. Context switch: saving the state of the running process in its PCB and loading the saved state of the next one when the CPU switches tasks.

3. Dispatcher: the module that gives CPU control to the process chosen by the short-term scheduler. The time it takes is the dispatch latency.

4. Thread: a lightweight process. Threads in one process share code and data, but each has its own stack, registers and program counter.

5. Semaphores: a binary semaphore takes only 0 or 1 (mutual exclusion). A counting semaphore takes any non-negative integer (a pool of identical resources).

6. Safe state: a state where the system can allocate resources to every process in some order and still avoid deadlock. That order is a safe sequence.

7–12

7. TLB: Translation Lookaside Buffer, a small fast cache of page-table entries. A hit avoids an extra memory access to the page table.

8. Fragmentation: internal is unused space inside an allocated block (fixed partitions, paging). External is free memory split into non-contiguous holes (variable partitions, segmentation).

9. Thrashing: high paging activity where a process spends more time swapping pages than executing.

10. File attributes: name, identifier, type, location, size, protection, and time/date/user identification.

11. Bit vector: one bit per disk block marks it free or allocated, so free blocks are found by scanning bits. It is simple and compact.

12. Trojan horse: a program that looks legitimate but, when run, captures user credentials or performs hidden harmful actions.

Part B

13. Process states and PCB

States: New (being created), Ready (waiting for CPU), Running (executing), Waiting (for an I/O or event), Terminated (finished).

New → Ready ⇄ Running → Terminated
        ↑        ↓
        └─ Waiting ┘ (I/O or event)

The PCB holds, for each process: process state, program counter, CPU registers, CPU-scheduling information (priority, queue pointers), memory-management information (base/limit, page tables), accounting information and I/O status (devices, open files). It is created with the process and removed when it ends.

State transition diagram

Important points

  • The PCB is the only record of a process the OS keeps; a context switch saves and reloads it.
  • Only one process per CPU is Running; many may be Ready or Waiting.

Explanation of each transition

  • New → Ready: the long-term scheduler admits the process after its PCB and memory are set up.
  • Ready → Running: the short-term scheduler selects it and the dispatcher gives it the CPU.
  • Running → Ready: a timer interrupt ends its time slice, or a higher-priority process arrives (preemption).
  • Running → Waiting: the process requests I/O or waits for an event such as a child finishing.
  • Waiting → Ready: the I/O completes or the event occurs; the process cannot go straight to Running.
  • Running → Terminated: the process finishes (exit) or is killed; the OS frees its resources.

PCB layout and its role

+-----------------------------+
| process state               |
| process number (PID)        |
| program counter             |
| CPU registers               |
| scheduling info (priority)  |
| memory info (base, limit,   |
|   page / segment tables)    |
| accounting info             |
| I/O status (devices, files) |
+-----------------------------+

When the CPU switches from process P0 to P1, the OS saves the state of P0 into PCB0 and reloads the state saved in PCB1. This is why the PCB is called the “repository of information” for a process. A new process is created by a system call such as fork(); the parent may wait for the child with wait(), and the child ends with exit().

  • Processes are of two kinds: system processes (run OS code) and user processes (run application code).
14. Scheduling queues and schedulers

Queues: job queue (all processes), ready queue (in memory, ready to run), device queue (waiting for an I/O device).

  • Long-term (job) scheduler: admits processes from the new pool to the ready queue and controls the degree of multiprogramming. Runs rarely.
  • Short-term (CPU) scheduler: picks the next ready process for the CPU. Runs most often.
  • Medium-term scheduler: swaps processes out of and back into memory to balance load.

Queueing diagram

Detailed answer

Scheduling queues are linked lists of PCBs. A new process joins the job queue, moves to the ready queue once admitted, and runs when the short-term scheduler picks it. A running process leaves the CPU for one of four reasons: it issues an I/O request (device queue), its time slice expires (back to the ready queue), it forks a child and waits, or it waits for an interrupt. After the event it returns to the ready queue until it terminates, when its PCB and resources are released.

Comparison of schedulers: the long-term scheduler runs in seconds or minutes and picks a good mix of I/O-bound and CPU-bound processes; the short-term scheduler runs every few milliseconds, so it must be very fast; the medium-term scheduler swaps out a process to reduce memory pressure and swaps it in later, which is what makes swapping possible.

  • An I/O-bound process spends more time doing I/O than computation; a CPU-bound process does the opposite.
  • If all processes are I/O-bound the ready queue is nearly empty and the CPU idles; if all are CPU-bound the device queues stay empty.
  • Context switching between processes is pure overhead: the PCB of the old process is saved and the PCB of the new one loaded.
  • Dispatcher hands the CPU to the chosen process; its delay is the dispatch latency.

Context switch (P0 to P1)

P0 running  -> interrupt or system call
            -> save state of P0 into PCB0
            -> reload state of P1 from PCB1
P1 running  -> ...later the same steps in reverse

During the switch the system does no useful work, so the overhead should be kept small. The time depends on hardware support, for example the number of registers to copy. Degree of multiprogramming is the number of processes in memory; the long-term scheduler controls it. When the load is stable, the rate at which processes are created equals the rate at which they leave the system.

Types of queue

  • Job queue: all processes in the system.
  • Ready queue: processes in main memory waiting for the CPU, usually a linked list with head and tail pointers to the PCBs.
  • Device (I/O) queue: processes waiting for a particular device; each device has its own queue.
  • The medium-term scheduler is added in time-sharing systems so that swapping can reduce the degree of multiprogramming when memory is short.
15. Banker’s algorithm

A deadlock-avoidance algorithm: a request is granted only if the system stays in a safe state.

Data structures: Available (free instances per type), Max (maximum demand), Allocation (currently held), Need = Max − Allocation.

Safety check: (1) Work = Available, Finish[i] = false. (2) Find a process with Finish = false and Need ≤ Work. (3) Work = Work + Allocation of that process, Finish = true, repeat. (4) If all Finish are true, the state is safe.

Resource request: if Request ≤ Need and Request ≤ Available, pretend to allocate, then run the safety check. Grant if safe, otherwise make the process wait.

Worked example

5 processes, resource types A, B, C. Available = (3, 3, 2).

Proc  Max      Alloc    Need=Max-Alloc
P0    7 5 3    0 1 0    7 4 3
P1    3 2 2    2 0 0    1 2 2
P2    9 0 2    3 0 2    6 0 0
P3    2 2 2    2 1 1    0 1 1
P4    4 3 3    0 0 2    4 3 1
Work = 3 3 2
P1 (1 2 2 <= Work) runs  -> Work = 5 3 2
P3 (0 1 1 <= Work) runs  -> Work = 7 4 3
P4 (4 3 1 <= Work) runs  -> Work = 7 4 5
P2 (6 0 0 <= Work) runs  -> Work = 10 4 7
P0 (7 4 3 <= Work) runs  -> Work = 10 5 7

Safe sequence: <P1, P3, P4, P2, P0>, so the system is in a safe state.

Detailed answer

The algorithm is named after a bank that never lends so much cash that it cannot satisfy all its customers. Each process must declare its maximum need in advance and must return resources in finite time. If a request would leave the system unsafe, the process waits even though the resources are free. The drawbacks: it needs the maximum demand in advance, the number of processes must be fixed, and its running time is of the order m × n² for m resource types and n processes. Because of these costs it is rarely used
